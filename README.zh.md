<h1 align="center">dsh-no-blank-sessions</h1>

<p align="center">点“新会话”时复用已有的空白草稿，不再堆出一堆空会话。</p>

<p align="center"><a href="README.md">English</a> | 中文</p>

“新会话”请求没有指定要复用的会话时，DSH 的会话控制器总是新建一个，所以空白会话会越积越多。它自己的检查还会把任何“没有完成过回合”的会话当成空白，哪怕这个会话被固定了、有种子或是被委派的。装上这个插件后，点“新会话”会先在同一个工作区里找一个空白草稿，找到就直接打开它；只有找不到可复用的空白会话时才新建。

## 什么算“空白”

满足下面全部条件的会话才会被复用：

- 从没用过：没有种子，不继承别的会话的内容，也不是子代理会话或其他被委派的会话。
- 历史里只有初始选择：代理预设、审批策略、模型、权限预设和沙箱模式。
- DSH 和其他插件在初始化时写下的记录不算“用过”：斜杠命令的记录，以及已经取消的排队消息。仍在队列里等着发送的消息算数，因为这个会话马上就要被用了。
- 在同一个工作区文件夹里；如果你选了代理预设，它的预设也要一样。
- 没有被固定，也没有被归档。

## 它还做了什么

- 对同一个工作区和预设，同时到达的多次“新会话”请求只做一次查找，所以连点两下不会建出两个会话。
- DSH 判断能不能复用一个在内存里或从磁盘恢复的会话时，用的是它自己的“是否空白”检查。插件按上面的规则把这个检查收紧了，有历史的会话不会被当成空白会话。
- 如果你同时用 OpenViking 记忆插件，并且关闭了自动记录或轮次同步，那么只有初始选择的会话，在你真正使用它之前不会去开启 OpenViking 会话。

只有你自己触发的“新会话”会被重定向。服务调用和被委派的会话仍然自己选会话 ID，和以前一样。

## 相近的插件

[dsh-session-drafts](https://github.com/ne-ilyxa/dsh-session-drafts) 也会让“新会话”复用空草稿，并且在侧边栏里多了一个草稿列表。两者都会改变“新会话”选会话的方式，请只装其中一个。它们同时装会怎样，没有测过。

## 安装

在 DSH 里打开**插件**，点**添加插件**，输入：

```
github:Vocllum/dsh-no-blank-sessions
```

或者在终端里：

```sh
dsh plugin --profile desktop add "github:Vocllum/dsh-no-blank-sessions"
```

桌面端：先打开一次，完全退出，运行命令，再重新打开。终端里没有 `dsh` 的话，在应用菜单里选**管理 dsh 命令…**安装。`dsh web` 用 `--profile web`。

需要 DSH `>=0.2.2-rc.5 <0.3.0`。插件包装了 DSH 会话控制器的两处内部接口（`create` 和 `agents.isBlank`）；DSH 没有提供它们时，插件只记一条警告，什么都不做。

## 卸载

在插件页移除即可。它不保存任何数据，卸载后原有行为自动恢复。

## 开发

```sh
node --test test/*.test.mjs
```

测试不需要任何依赖，它们用仿照真实记录形状的会话历史去跑插件的 `create` 和 `isBlank`。
